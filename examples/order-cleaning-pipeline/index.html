一行订单怎样走完清洗流水线

这张卡片是套件的示例：它跟着同一行订单走完三个阶段。数据是虚构的，所以每张表都标了“示意数据”。

每行是一笔订单，核心是“买了什么品类”和“给它打的标签”。标签的写法是 品类@标签，来自不同数据源，写法并不统一：

order_idcategorylabelqty
A-1001(空)鞋类@Running Shoes #21
A-1002服饰服饰@上衣 左袖3
A-1003其它体系其它体系@杂项2

顺序是有原因的：先补全，才能判断一行到底在不在体系里。下面跟着 A-1001 走一遍，点标题可折叠每一站。

category = (空)
label    = 鞋类@Running Shoes #2
 
category = 鞋类
label    = 鞋类@Running Shoes #2
 品类为空的行没法判断属于哪个体系，必须先从标签的 @ 前半段补出来；否则下一站会把它当成“体系外”误删。

三行都进来：A-1001 鞋类，A-1002 服饰，A-1003 其它体系。

只剩 A-1001 和 A-1002。A-1003 被删除。

 训练只覆盖约定的品类体系，体系外的行留着只会变成噪声标签。

带方位词、编号、大小写不一的原始标签（见下面的对比）。

统一成规范短语，同一个部件只剩一种写法。

 同一部件被写成很多近义标签，会互相变成假的反例；规范化把它们并成一个。

下面把 A-1001 和 A-1002 的标签处理前后放在一起，变化的部分会自动高亮：

鞋类@Running Shoes #2 服饰@上衣 左袖 鞋类@running shoes 服饰@上衣 袖
